# Feature comments for the product
The team reviewed the app and admin portal, quite a few amendments and features changes:

## App Journey - Exercise and question
- **Question Pool**: 1 article should have a large volume of questions (Question pool). Each exercise should randomly pick questions from this question pool.
- **Question Types**: Under the current prompt, there are 4 types of questions (e.g. meaning of words, sentence meaning, etc...). We should have 6-8 types of questions. different level of exercises will take numbers of types of questions. E.g., type A 10 questions, Type B 8 questions, etc, to formulate an exercise. Final list of **Question Types** to be confirmed soon.
- In user dashboard, each exercise result should be counted across types of questions.
- **Question Format**: Currently there are only MC questions for 4 options. There should be more format of questions, e.g short questions, long questions, fill in the blanks, etc.Final list of **Question Format** to be confirmed soon.
- The team decided to drop "form 1 to form 3 levels". This market is not suitable for phase 1 MVP.

## Expected Finishing Time for exercise
- In admin portal, each exercise should have an expected finishing time upon creation. (filled in by admin)
- **Time counter**: During the exercise, the user should be seeing a timer counting time used at the app screen.
- In user dashboard, the user can see how much time they spent to finish that exercise and the gap of admin advised time limit.
- In user dashboard, the user can see how much time spent on **Question Types** per each exercise.

## Revision chapter and weight training chapter
- **Revision chapter**: The system should record the mistakes from the user. The user can pick **Revision chapter** from dashboard. Each **Revision chapter** should contain 15-20 mistakes made by the user before.
- **Weight training**: The user can pick **Question Types**'s **Weight training** chapter from dashboard. Each **Weight training** should contain 15-20 **Question Types**'s questions.
- For both new types of exercises, the raw sentence/ part of article will be extracted for question usage.

## Admin portal
- Let's separate article creation and exercise creation in concept. The **Article library** contains all the articles, no matter quizzes are generated or not. 
- For **Add a new article**, user will be filling in the current form as usual, but the system will not run Quiz prompting yet. it only generates a new article in article library with the translation prompt.
- Break down **Article library** into **Article library - Listing** which only has the article title, generated time, has quizzes or not, and a detail button.
- **Article library - Detail** should have editors for `Article JSON`, a **Quiz prompt selector**, and generated `Quiz JSON`.
- The **Quiz prompt selector** should be linked to a new section of admin portal named **Quiz prompt MGT**. 
- The **Quiz prompt MGT** should be able to add new prompt, edit existing prompt and delete existing prompt.

## Admin portal - GO LIVE
- We would like to deploy the admin portal to a LIVE database for the admin to start working on creation of exercises.
- We expect a public web link of the admin portal, a very basic login auth for security.
- We expect the mobile app has a **Update** button from dashboard to take the latest exercises from the admin portal database.

## Commercialisation
- The app should have some advertisement sections, ad banners/ videos. And these ads should link up advertising platform for income.
- Free tier user should be seeing the advertisement.
- This should be considered together with subscription plans in later phases.
